# Kuzgram

Закрытый чат для одной семьи: общая лента на всех, вход по одноразовым кодам,
уведомления на заблокированный телефон. Разворачивается на домашнем сервере
одной командой и не требует ни аккаунтов, ни облаков, ни чужих серверов.

Node + Express + SQLite на бэкенде, голый HTML/CSS/JS на фронте — без сборщика,
бандлера, фреймворков и TypeScript. Четыре зависимости, ни одной dev-зависимости.

Главной задачей было заставить Web Push дойти до iPhone, когда приложение
полностью закрыто, а телефон лежит с заблокированным экраном. Это работает.

## Возможности

- Один общий чат на группу до десяти человек, текстовые сообщения
- Пуш-уведомления на iOS 16.4+ и Android: имя автора в заголовке, текст в теле,
  тап открывает приложение, а не вкладку браузера
- Вход по одноразовому инвайт-коду, коды выдаёт CLI на сервере
- Отдельный код привязывает второе устройство к тому же человеку
- Ставится на домашний экран и открывается своим окном, без адресной строки
- Оптимистичная отправка: сообщение появляется мгновенно, при обрыве связи
  краснеет и повторяется по тапу
- Смайлики: панель в композере и крупный показ сообщений из одних эмодзи

**Чего нет и не будет.** Файлов, картинок, реакций, тредов, статусов прочтения,
редактирования, удаления, личных переписок, регистрации по почте. Это не клон
телеграма, а ровно то, что нужно семье.

## Быстрый старт

Нужен только Docker — Node на хосте не требуется.

```bash
git clone https://github.com/egerkuzma/kuzgram.git
cd kuzgram

cp .env.example .env
docker run --rm node:22-alpine npx -y web-push generate-vapid-keys   # пару ключей в .env

docker compose up -d --build
```

Приложение слушает порт 3000. Дальше нужен прокси с TLS — см. следующий раздел.

```bash
docker compose logs -f kuzgram      # логи
docker compose restart kuzgram      # перезапуск
docker compose up -d --build        # обновление после правок в коде
docker compose down                 # остановить
```

## Развёртывание

Приложение слушает `0.0.0.0:3000` и говорит по обычному HTTP. TLS терминируется
снаружи — на домашнем роутере, nginx или любом другом прокси. Сертификатов
и редиректов на https внутри Node нет намеренно.

**Домен обязан быть на https.** Без защищённого соединения Safari не даст ни
service worker, ни уведомлений, и смысл проекта пропадает. Дальше в примерах
адрес обозначен как `https://chat.example.com` — подставь свой.

База и WAL-файлы лежат на хосте в `./data`, поэтому пересборка образа переписку
не трогает. Контейнер работает от непривилегированного пользователя,
`restart: unless-stopped` поднимает его после перезагрузки машины, а healthcheck
раз в полминуты дёргает `/api/vapid-public-key`.

Переменные окружения:

| Переменная | Обязательна | Что делает |
|---|:--:|---|
| `VAPID_PUBLIC`, `VAPID_PRIVATE` | да | Пара ключей для Web Push |
| `VAPID_SUBJECT` | да | Контакт для push-сервиса, `mailto:` |
| `KUZGRAM_DB` | нет | Путь к базе, в контейнере `/data/kuzgram.db` |
| `JOIN_MAX_FAILS`, `JOIN_WINDOW_MS` | нет | Порог блокировки перебора кодов, по умолчанию 15 за 10 минут |

## Приглашения и доступ

Кодами управляет только CLI на сервере, самообслуживания нет.

```bash
docker compose exec kuzgram node bin/invite.js                # новый участник
docker compose exec kuzgram node bin/invite.js --user Маша    # ещё одно устройство
docker compose exec kuzgram node bin/invite.js --user 2       # то же самое, по id
docker compose exec kuzgram node bin/invite.js --ttl 2        # срок жизни 2 часа
```

Код одноразовый и живёт 48 часов. Новому участнику при входе нужны код и имя,
коду на второе устройство — только код: имя подставится само.

**Каждое устройство требует своего кода.** На iOS у приложения с домашнего
экрана и у Safari разные хранилища, токен между ними не переезжает.
Переустановка иконки с «Домой» тоже стирает токен.

Отзыв доступа — удалить строку из `tokens`:

```sql
DELETE FROM tokens WHERE user_id = 3;   -- выкинет со всех устройств
```

Удалить самого участника сложнее: на него ссылаются сообщения, токены, подписки
и инвайты, внешние ключи включены. Порядок — подписки, токены, сообщения,
инвайты (`used_by` и `for_user`), затем сам пользователь.

## Установка на телефон

Приложение ставится на домашний экран и открывается своим окном, без адресной
строки и отдельной карточкой в списке задач.

### iPhone

1. Открыть `https://chat.example.com` в Safari
2. Поделиться → «На экран Домой»
3. Запустить **с иконки**: из вкладки Safari push не заработает
4. Войти по коду → тапнуть «Включить уведомления» → «Разрешить»

Диалог разрешения показывается только по прямому тапу и только один раз. Если
нажать «Не разрешать», iOS больше не спросит, и лечится это лишь удалением
иконки с «Домой» и повторной установкой.

### Android

1. Открыть `https://chat.example.com` в Chrome
2. Тапнуть «Установить» в шапке приложения. Если кнопки нет — меню Chrome
   (три точки) → «Установить приложение»
3. Запустить с иконки, войти по коду, включить уведомления

Кнопка в шапке появляется сама, когда Chrome считает приложение готовым к
установке, и исчезает после установки. На iOS её не будет: Safari такого
события не присылает.

В отличие от iPhone, Android разрешает пуши и во вкладке браузера, но ставить
на домашний экран всё равно стоит — иначе уведомления привязаны к Chrome
и теряются вместе с его данными.

## Устройство проекта

| Файл | Роль |
|---|---|
| `server.js` | Роуты, статика, `sw.js` с `no-cache`, заголовки безопасности |
| `db.js` | SQLite: схема, миграции, подготовленные запросы, транзакция погашения инвайта |
| `auth.js` | Токены (32 случайных байта), middleware `Authorization: Bearer` |
| `push.js` | Рассылка через web-push, чистка мёртвых подписок |
| `bin/invite.js` | Генерация кодов |
| `public/app.js` | Экраны входа и чата, лента, отправка, подписка на пуши |
| `public/transport.js` | Доставка сообщений: опрос раз в 2.5 с. Меняется на WebSocket без правок остального фронта |
| `public/sw.js` | Показ уведомлений, клик по ним, оффлайн-заглушка |
| `Dockerfile` | Три стадии: зависимости, тесты, рабочий образ |
| `docker-compose.yml` | Том `./data`, `.env`, порт 3000, автоперезапуск |

Таблицы: `users`, `invites`, `tokens`, `messages`, `subscriptions`. Схема
создаётся и мигрируется при старте.

API — всё, кроме `join` и `vapid-public-key`, требует токен:

| Метод | Роут | Назначение |
|---|---|---|
| `POST` | `/api/join` | Погасить код, получить токен |
| `GET` | `/api/me` | Текущий участник |
| `GET` | `/api/messages?after=<id>` | Сообщения новее указанного id, до 100 |
| `POST` | `/api/messages` | Отправить сообщение и разослать пуши |
| `POST` | `/api/subscribe` | Сохранить push-подписку |
| `GET` | `/api/vapid-public-key` | Публичный ключ для подписки |

## Тесты

Отдельная стадия сборки, Node на хосте не нужен. Сборка падает на красных тестах.

```bash
docker build --target test .
```

63 проверки на встроенном `node:test`, без единой тестовой зависимости. Каждый
файл поднимает свою базу во временном каталоге и подменяет отправку пушей, так
что сеть не задействована.

| Файл | Что покрывает |
|---|---|
| `test/db.test.js` | Схема и миграции, погашение инвайтов, токены, сообщения, подписки |
| `test/api.test.js` | Все роуты: коды ответов, валидация, заголовки, рассылка при отправке |
| `test/push.test.js` | Рассылка: кому уходит, TTL и urgency, удаление на 404/410, живучесть при 500 |
| `test/sw.test.js` | Service worker: перехват навигации, оффлайн-заглушка, показ уведомлений, клик по ним |
| `test/security.test.js` | Доступ: чтение без токена, кривая авторизация, перебор кодов, гонка за инвайт, утечки статики |

Покрытие бэкенда: `auth.js` 100%, `db.js` 100% строк, `push.js` 96.7%,
`server.js` 96.8%. Незакрыты только ветка «VAPID не настроен» и блок `listen`.
Фронт покрыт частично: service worker исполняется в изолированном контексте
с подставными `self` и `fetch`, а экраны и лента проверяются руками — для них
понадобился бы DOM-движок, то есть лишние зависимости.

## Модель безопасности

Чат закрытый: без валидного токена наружу не отдаётся ни одно сообщение и ни
одно имя. Токена нет ни у кого, кроме тех, кто погасил инвайт-код.

**Что защищает вход**

- Регистрация только по коду: других путей завести пользователя в API нет
- Код одноразовый, гасится в той же транзакции, где создаётся пользователь, —
  параллельные запросы одним кодом дают ровно одного участника
- Код живёт 48 часов и потом не принимается
- Перебор: 15 промахов по несуществующим кодам за 10 минут — и `/api/join`
  отвечает 429 до конца окна. Считаются только выстрелы мимо, повторный тап
  «Войти» с уже использованным кодом блокировку не приближает
- Пространство кодов — 31⁸ ≈ 8·10¹¹ комбинаций, алфавит без похожих символов
- Токен — 32 случайных байта из `crypto.randomBytes`, живёт до удаления строки

**Что защищает страницу**

- CSP `default-src 'self'` без `unsafe-inline`: инлайн-скриптов на странице нет,
  поэтому политику можно держать строгой. Плюс `nosniff`, `X-Frame-Options: DENY`,
  `frame-ancestors 'none'`, `Referrer-Policy: no-referrer`
- CORS-заголовков нет намеренно: чужая страница не прочитает ответы API.
  Токен ездит в заголовке, а не в куке, поэтому CSRF неприменим
- Весь пользовательский текст попадает в DOM только через `textContent`
- HSTS на год
- `.env` и файл базы — права `600`

**Известные компромиссы**

- **Блокировка перебора общая, не по IP.** Если прокси не проставляет
  `X-Forwarded-For` (домашние роутеры этим грешат), настоящий адрес клиента до
  приложения не доходит и различать источники нечем. Побочный эффект: устроивший
  перебор на 10 минут перекроет регистрацию всем. Читать переписку это не даёт.
  Когда заголовок есть, счётчик несложно сделать поадресным
- **http:// может отвечать.** Соединение на 80-м порту принимает прокси,
  приложение о схеме запроса не знает вовсе. HSTS закрывает вопрос для браузеров;
  полный отказ настраивается на прокси — не пробрасывать порт 80
- **Сквозного шифрования нет.** Текст уходит в пуш и виден Apple, в базе лежит
  открытым. Для семейного чата это осознанный выбор
- **Токены в базе в открытом виде.** Хранить их хэш имело бы смысл, если бы база
  не содержала саму переписку; здесь это ничего не добавляет

## Диагностика

**Контейнер не стартует, в логах жалоба на VAPID.** `.env` не подхватился:
`env_file` ищет его рядом с `docker-compose.yml`. Проверить —
`docker compose exec kuzgram env | grep VAPID`.

**Снаружи не открывается.** Сначала контейнер: `docker compose ps` должен
показывать `0.0.0.0:3000->3000/tcp`, а `docker compose logs` — строку
«kuzgram слушает». Если порт на месте, вопрос к прокси: доходит ли до него
запрос и куда он его отправляет.

**После пересборки образа пропала переписка.** База должна лежать на томе
`./data`, а не внутри контейнера: проверить `KUZGRAM_DB=/data/kuzgram.db`
и что каталог примонтирован.

**Кнопки «Включить уведомления» нет.** Разрешение уже выдано — кнопка прячется.
Проверить в Настройках → Уведомления → Kuzgram.

**Кнопка есть, диалог не появляется.** Открыто из Safari, а не с «Домой». Либо
iOS ниже 16.4 — там Web Push нет вовсе.

**`[push] отправлено 0` в логе.** Подписок в базе нет. После переустановки
приложения подписку надо оформить заново.

**`[push] 410, подписка удалена`.** Нормальное поведение: подписка протухла,
сервер сам её выкинул. Оформить заново с устройства.

**Пуш ушёл, а на телефоне тихо.** «Фокусирование», режим экономии энергии либо
выключенные баннеры для Kuzgram. Apple при экономии энергии задерживает доставку.

**Правки в `sw.js` не подхватываются.** Отдаётся с `Cache-Control: no-cache`,
в `activate` сносятся все кеши, но старый воркер может ещё висеть активным:
полностью закрыть приложение и открыть заново.

**Вход просит код, хотя вчера пускал.** Токен жил в хранилище, которое стёрлось
(переустановка иконки, очистка данных Safari). Выдать код на устройство.

**«Срок действия кода истёк».** Коду больше 48 часов, выдать новый.

**«Слишком много попыток».** Сработала защита от перебора. Отпустит через
10 минут после последней попытки, перезапуск контейнера тоже сбрасывает счётчик.
